# Alimida Roadmap

## 1. 目的

この文書は、Alimida の長期的な方向性を整理するためのロードマップである。

Alimida は、単なる人工言語仕様ではなく、AI時代の言語学習・AIとの対話・人間同士の補助的な共通語を見据えて段階的に発展させる。

本ロードマップでは、各バージョンで何を重視し、どの順番で仕様を拡張するかを定義する。

---

## 2. 長期ビジョン

Alimida は、AI時代のための **学習しやすく、構造化しやすく、話しやすい補助言語** を目指す。

長期的には、以下の3つの方向性を持つ。

```text
1. 文法学習用のミニ言語
2. AIと人間の間に置く構造化対話言語
3. 人間同士でも使える簡易共通語
```

特に重要な方向性は、自然言語とプログラミング言語の中間にある、**人間が読めるロジック言語** としての発展である。

Alimida は、プログラミング言語のように硬すぎず、通常の自然言語ほど曖昧すぎない言語を目指す。

---

## 3. 基本方針

Alimida の仕様拡張では、次の方針を優先する。

```text
- 人間にも読みやすい
- AIにも構文分解しやすい
- 曖昧さが少ない
- 初学者が文法構造を学びやすい
- 発音しやすい
- 語彙・文法を増やしすぎない
- 仕様追加より、使用例と検証を重視する
```

Alimida は、最初から完全な公用語や万能言語を目指さない。
まずは小さく使える言語として安定させ、その後、用途に合わせて段階的に拡張する。

---

## 4. 主要ユースケース

Alimida の主要ユースケースは、以下の通りとする。

### 4.1 文法学習

初学者が、主語・動詞・目的語・時制・否定・関係語などの文構造を理解するための教材として使う。

```text
mi ta nu sena koda.
私は構造を学ばなかった。
```

このような文を通じて、文の構成要素を明示的に学べるようにする。

### 4.2 多言語学習の足場

Alimida を、日本語・英語・その他の言語を学ぶ前の中間教材として使う。

自然言語の複雑な例外や不規則性に入る前に、文法の基本構造を把握することを目的とする。

### 4.3 AI添削・翻訳比較

AIが Alimida 文を構文分解し、標準形・許容形・非標準形を説明できるようにする。

```text
主語: mi
時制: ta
否定: nu
動詞: sena
目的語: koda
```

このように、AIが文の構造を明示できることを重視する。

### 4.4 AIとの構造化対話

条件、目的、制約、理由、手順、優先度などを、AIがロジックとして扱いやすい形で表せるようにする。

```text
si user nidi buko, dan AI pako lista.
もしユーザーが本を必要とするなら、AIはリストを作る。
```

このような文を、将来的には構造化データへ変換できることを目指す。

### 4.5 簡易共通語

長期的には、人間同士の簡単な会話にも使える補助言語を目指す。

ただし、会話用の自然さは、AI向けの明示性と衝突する場合がある。
そのため、将来的には標準形と口語許容形を分けて扱う。

## 5. フェーズ別ロードマップ

## Phase 1: v1.x — 学習用ミニ言語として安定させる

### 目的

Alimida を、初級文法学習に使える小さな言語として安定させる。

v1.x では、仕様を大きく増やすより、既存仕様を教材として使える状態にする。

### 重視すること

```text
- 基本文法の安定
- 基本語彙の安定
- 例文の充実
- 学習順序の整理
- AI添削の前提づくり
```

### 主な作業

```text
- 例文100本を作成する
- 文法項目ごとのミニレッスンを作る
- 語彙レベル分けを行う
- 標準形 / 許容形 / 非標準形の練習問題を作る
- 基本体系語彙を使った例文を追加する
- 関係語の一覧表を教材用に整理する
```

### v1.x で検討する文法

必要に応じて、以下を検討する。

```text
- 存在表現
- 所有表現
- 可能表現
- 希望表現
- 必要表現
- 理由表現
- 目的表現
- 基本的な比較表現
```

ただし、例文や教材で必要になるまでは急いで採用しない。

---

## Phase 2: v1.5前後 — AI添削・翻訳比較に使う

### 目的

AIが Alimida 文を構文分解し、添削・説明・翻訳比較できるようにする。

### 重視すること

```text
- AIが勝手に仕様を拡張しない
- 標準形を優先する
- 許容形を誤り扱いしない
- 非標準形は理由つきで修正する
- 未定義語は推測せず確認する
```

### 追加候補ファイル

```text
docs/07_ai_guidelines.md
```

### 主な作業

```text
- AI添削ルールを作る
- 構文分解フォーマットを作る
- エラー分類を作る
- 標準形への修正方針を定義する
- 翻訳比較テンプレートを作る
- 未定義語の扱いを決める
- AIが新語を勝手に作らないためのルールを作る
```

### 構文分解例

```text
mi ta nu sena koda.
```

```json
{
  "subject": "mi",
  "tense": "ta",
  "negation": "nu",
  "verb": "sena",
  "object": "koda"
}
```

このような分解を、AIが安定して出力できることを目指す。

---

## Phase 3: v2.x — Logic Alimida

### 目的

Alimida を、AIとの対話やロジック化に強い言語へ発展させる。

この段階では、通常の会話だけでなく、条件、目的、制約、理由、手順などを明示できるようにする。

### 重視すること

```text
- 条件を明示できる
- 理由を明示できる
- 目的を明示できる
- 制約を明示できる
- 手順を明示できる
- 優先度を明示できる
- AIが構造化データへ変換しやすい
```

### 主な検討項目

```text
- 条件
- 理由
- 目的
- 可能
- 必要
- 希望
- 義務
- 許可
- 禁止
- 比較
- 定義
- 参照
- 順序
- 範囲
- 優先度
- 入出力形式
```

### 目標例

```text
si user nidi buko, dan AI pako lista.
```

```json
{
  "type": "conditional",
  "if": {
    "subject": "user",
    "verb": "nidi",
    "object": "buko"
  },
  "then": {
    "subject": "AI",
    "verb": "pako",
    "object": "lista"
  }
}
```

Alimida を、人間が読める構造化プロンプトのように扱えることを目指す。

---

## Phase 4: v3.x — Spoken / Public Alimida

### 目的

Alimida を、人間同士の簡単な会話にも使える補助的な共通語へ広げる。

### 重視すること

```text
- 発音しやすい
- 短く話せる
- 省略しても大きく誤解しない
- 丁寧さを表現できる
- 聞き返しや確認ができる
- 文化差が出にくい
```

### 主な作業

```text
- あいさつ表現
- 依頼表現
- 返答表現
- 確認表現
- 聞き返し
- 感情表現
- 合意・反対
- 断り
- 会話修復表現
- 口語許容形
```

### 標準形と口語形

将来的には、次の2層を分けて扱う。

```text
Standard Alimida:
学習・AI・文法分解向け。明示的で論理的。

Spoken Alimida:
会話向け。省略や短縮を一部許容。
```

v3.x では、話しやすさを高める一方で、Standard Alimida の明示性を壊さないようにする。

## 7. 仕様追加の判断基準

新しい語彙・文法・表記ルールを追加する場合は、次の基準で判断する。

```text
1. その仕様は、どのユースケースに必要か。
2. 既存の文法で表せないか。
3. 曖昧さを増やさないか。
4. 学習負荷に見合う価値があるか。
5. AIが構文分解しやすいか。
6. 発音しやすいか。
7. 例文や教材で実際に使う予定があるか。
8. Standard Alimida と Spoken Alimida のどちらに属するか。
```

仕様追加は、思いつきで行わない。
必ず、用途・例文・AI処理・学習負荷を確認してから採用する。

---

## 8. 当面やらないこと

以下は、短期的には扱わない。

```text
- 完全な自然言語化
- 大量の語彙追加
- 複雑な敬語体系
- 地域差や方言
- 文学表現
- 詩的表現
- 曖昧さを前提とした表現
- 高度な比喩表現
- 例外的な発音規則
- 不規則変化
```

Alimida は、まず規則性・学習しやすさ・AI処理しやすさを優先する。


## 10. ロードマップの更新方針

このロードマップは固定ではない。

Alimida の仕様、教材、AI添削、会話用途が進むにつれて、必要に応じて更新する。

ただし、次の原則は維持する。

```text
- まず小さく使える形にする
- 使ってから仕様を増やす
- 曖昧さを増やさない
- AIが扱いやすい構造を保つ
- 人間が学びやすいことを優先する
```

Alimida は、仕様を増やすことで完成するのではなく、実際に使える場面を増やすことで成長させる。
